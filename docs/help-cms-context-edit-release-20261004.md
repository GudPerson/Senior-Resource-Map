# Help Centre owner editing release — 4 October 2026

## Scope and authority

Joshua approved the contextual owner-editing prototype and explicitly requested
implementation, commit, push and production deployment. The production Help
Centre becomes the entry point for owner editing: open an article or topic,
choose Edit, change the relevant block, and preview or save the library draft.
Management, history and publication remain secondary tools.

This release reuses existing authorisation, private CMS storage, concurrency,
media and publication APIs. It does not add a schema, credential, AI budget or
published-content change. Dedicated publisher service tokens remain pending;
the release does not imply that publishing is activated.

## Regression boundaries

- Ordinary readers retain the existing published article renderer and access.
- Owner controls require the existing server capability; a role or URL alone
  does not authorise private editing.
- An identity-scoped CMS session retains the whole library draft while moving
  between article, topic, preview, management and history views.
- Draft previews omit reviewed stamps; private images use authorised blob URLs.
- Save remains library-wide and does not publish. History restore remains
  library-wide. Conflicts retain current edits.
- Article and section identities, immutable addresses/access, conceptual answer
  paragraph counts, stable step attachments and media limits remain protected.
- Identity, role and User View changes clear private state. Upload generation,
  upload locks, publication review and completion safeguards remain in place.
