## Locked Achievements

- Owner My Map and owner Print View keep CareAround's existing Leaflet map
  model: pins, clustering, camera movement, card-to-pin focus, reset behavior,
  mobile full-map behavior, list interactions, QR, and attribution.
- Detailed map remains an optional fixed-surface basemap inside the existing
  Leaflet `MapContainer`; it replaces only the basemap surface, not the
  interaction model.
- Detailed map activates automatically at displayed zoom step 15 when the map
  viewport/camera is inside covered detailed-map bounds. Zoom 14 stays on the
  regular map, and zoom 16 remains Detailed when covered.
- Owner Print View keeps Detailed available at displayed step 15 after zooming,
  panning, or resizing the print map frame, including large/full-map layouts.
- The fallback copy says the regular map is still shown; it must not resurrect
  the older `Standard map is still on` wording.
- Map appearance supports Default and Gray detailed-map styles using the
  versioned native-scale asset roots.
- Owner Print View is intentionally simplified:
  - downloads are `Save PNG` or `Save 2 PNGs`, plus `Save PDF`;
  - the old user-facing Print Master action is not shown;
  - the redundant high-resolution/page-format controls are not shown;
  - layout choices are `Balanced`, `Side map`, and `Full map`;
  - map width applies only to `Balanced` and `Side map`.
- Print resource badges keep readable minimum sizes and matching category
  colours across preview and export surfaces.
- Future map work must keep detailed-map chunks lazy-loaded, viewport-bounded,
  off-screen unloaded, attribution visible, and live OneMap basemap-tile
  requests absent while Detailed is active.

## Regression Gate For Future Map Work

Before any future commit or deploy that touches My Map, `DirectoryMap`, fixed
surfaces, map settings, or Print View:

1. Read this manifest, `docs/regression-ledger.md`, `docs/session-handoff.md`,
   and `docs/release-checklist.md`.
2. Run the focused map/print tests listed above.
3. Run the exact production-configured client build with all detailed-map roots.
4. Inspect the built and deployed bundles for the markers listed in
   `Verification`.
5. Explicitly verify the custom domain serves the same validated bundle after
   any Pages deployment. Do not rely on a Git-triggered Pages build alone.

## Known Limits

- Authenticated browser smoke depends on an existing user session or smoke
  credentials. If credentials are unavailable, record that clearly and use
  bundle, public route, API health, and user-assisted owner UAT as the release
  gate.
- A long-running Chrome process may keep stale modules after a Pages release.
  Verify production in a fresh tab/session before treating that as an app
  regression.

## Recommended Next Step

- For the next map-related change, start from `map-stable-2026-07-23`, make one
  narrow branch, and treat any missing Detailed-at-15 behavior, old Standard
  fallback wording, old `Save A3 PDF` label, or visible Print Master action as
  a release blocker.
