# Help CMS publishing activation correction

Date: 5 October 2026 (Asia/Singapore)

The owner previously approved dedicated publishing credentials, the CMS production release, and first publication of the existing approved Help library. The saved workspace was compared exactly with its approved source: 48 articles, 11 topics, zero attachments, and no editorial, order, archive or access changes. Credentials were handled privately; their values are absent from application source and release evidence.

The first real publication exposed two distinct blockers. The Worker request helper used `redirect: 'error'`, which Node accepted but the actual production-compatible workerd runtime rejected before network I/O. Both dispatch and job reconciliation share that helper; final content readiness uses it too. A direct retry of the exact frozen approved snapshot reached the private job, which then failed before content preparation, quality gates or production upload because Worker release provenance was unavailable. Cloudflare metadata confirmed the credential-triggered Worker version lacked the required Git source tag. The failed receipt was accepted; failed evidence is retained privately rather than relabelled as a successful release.

The code correction is limited to the CMS publisher's shared fetch helper. It uses `manual` redirect handling and explicitly refuses every 300–399 response, preserving the existing 15-second abort timeout, fixed URLs, credential headers, immutable dispatch inputs, owner boundary and receipt rules. It never follows a redirect with credentials. The Node-only content adapter is unchanged. [Cloudflare's runtime source](https://github.com/cloudflare/workerd/blob/main/src/workerd/api/http.c%2B%2B) and the isolated actual-runtime reproduction provide the compatibility evidence.

Local validation passed: 1,146 server tests, 53 CMS tests, 912 client tests plus five environment checks, 12 compiler tests, 104 map checks, static checks, the locked production client build and Worker dry run. Seven added tests exercise dispatch identity, all redirect status codes, metadata/dispatch/job/readiness refusal, running-job reconciliation and timeout cleanup. The actual bundled helper passed 11 workerd cases with fictional outbound responses and no real network; the old helper separately reproduced dispatch/reconciliation failure and unavailable readiness. This runtime proof is distinct from mocked Node tests and live publication acceptance.

Release acceptance requires configuring the new approved public source pin before the final tagged Worker deployment, preserving all existing secrets and bindings, and releasing from clean fetched main. Verify paired application source provenance, the unchanged approved content on Help/Guide/client, exact public artifact delivery and ordinary HTML behavior. Then create a fresh baseline publication for the new source; never rewrite or retry the old frozen source against a new main revision. Completion requires the exact private job, all release gates, acknowledged `published` receipt and cleared lock. These production checks remain separate from the local passes above.

The correction adds no database migration, account/role change, resource write, synthetic public article, paid model call or AI budget change. Later application releases must still carry the current published CMS content privately and satisfy the existing live-content guard.
