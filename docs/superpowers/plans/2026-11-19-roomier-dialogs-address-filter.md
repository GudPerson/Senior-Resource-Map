## Task 2 — Search, pinned completion and selection helpers

**Files** — Create `client/src/lib/mapAreaAddressSearch.js`, `client/src/lib/pinnedAreaAddressCompletion.js`, `client/src/lib/matchingSelection.js`, and `client/src/lib/manageMapSavedSelection.js`. Extend `client/src/lib/myMapResourceSelection.js`. **Interfaces**

- `normalizeAreaAddressQuery(value: string): string[]`, `createAreaAddressSearchIndex(rows: AddressRow[]): { row: AddressRow, text: string }[]`, and `filterAreaAddressSearchIndex(index, terms: string[]): AddressRow[]`. Each index item retains its original row reference and the row’s postal string is used for exact six-digit matching. An `AddressRow` is the existing provider row shape with nonempty string `id` and `postalCode` plus its existing address fields. UI bypasses the index until a query is active.
- `validatePinnedAreaAddressPage(page, {snapshotSha256, total, offset, limit, acceptedIds}): AddressRow[]` validates existing DTOs without mutating `acceptedIds`. `createPinnedAreaAddressCompletion({fetchPage})` accepts the existing `findSnapshotAddressesWithinArea` request shape. Return `start({area, scopeKey, snapshot, total, rows}): Promise<void>`, `resume(): Promise<void>`, `reset(): void`, `getSnapshot()` and `subscribe(listener): unsubscribe`. `rows` is an explicit verified prefix, independent of the last response offset. Status is `idle | preparing | ready | error | changed`. Snapshots expose `{status, progress:{confirmed,total}|null, completedRows: AddressRow[]|null, error}`. The controller publishes rows only on `ready`, resumes only the last active failed session and cancels with a generation fence and `AbortController`.
- `getMatchingSelectionState(selectedKeys, matchingKeys): {matchingCount, selectedMatchingCount, checked, mixed}` and `updateMatchingSelection(selectedKeys, matchingKeys, checked): Set<string>`. Both consume the matching complete eligible keys. Each update returns a new Set and preserves outside keys.
- `updateMatchingSavedSelection(selectedKeys, matchingAssets, savedAssets, checked): {selectedKeys: Set<string>, retainedHostNames: string[]}` builds on matching-set updates and the existing Saved offering host rule. Use composite keys and index available hard places by ID and trimmed address once per transaction. A place retained due to a selected offering is reflected in the result and existing keep-place feedback.
- `mergeRetainedMyMapAssets(currentAssets, selectedSavedAssets, retainedExistingKeys): AssetRef[]` in `myMapResourceSelection.js` supplies the existing delta builder with selected Saved refs plus current authoritative matching retained refs. By construction, absent retained keys cannot become POST additions.
