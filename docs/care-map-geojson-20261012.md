# Care Map GeoJSON import — release candidate

Approved scope: extend Import boundaries with `.geojson` and `.json` containing GeoJSON, using the existing preview, area selection and appearance controls. Work starts from accepted `52c482a49f2fcd795614a7e0d84c07f50f81403c` on `codex/care-map-geojson-20261012` in the maintained release checkout. The dirty primary and personal-place retry candidate remain preserved.

A separate decoder accepts FeatureCollection, Feature, Polygon and MultiPolygon in WGS84 longitude/latitude. Shared ring checks retain all original coordinates and source order, removing only the repeated closing coordinate. Multipart groups and holes remain one private, selectable, hideable annotation. Invalid or unsupported features have explicit skipped reasons; mixed geometries, non-zero altitude and projected/unknown CRS are refused without coordinate repair or external requests. Labels are plain text, and descriptions/remote properties are not imported. Dialog and runtime Guide instructions cover all four locales; authored Help content remains unchanged.

Backward compatibility is deliberate: decoded GeoJSON uses the already-released imported-boundary wire representation, including its historical `kml` discriminator. That marker is a geometry/storage contract, not an assertion of original file provenance. No new annotation discriminator is persisted: current cached clients retain all corners, part metadata, exact rendering and privacy when viewing/editing these imports. Annotation normalization, renderer, toolbar, owner API validator and shared geometry limits are byte-identical to the accepted source. No schema, map camera, pin, media, sharing or saved-view behavior change is required.

Limits remain 2 MB / 200 file entries, 100 map annotations, 1,000 original corners per polygon part including its holes, 10,000 original corners per geometry and 20,000 combined stored points per map. File preview may contain more than the selected map capacity; confirmation rejects the complete batch when selected areas plus existing annotations exceed it. Preview extent calculation avoids a large function-argument spread without altering coordinates.

Reproduce with a named multipart GeoJSON and hole: preview two areas and a skipped pin, deselect one, adjust appearance, confirm, wait for Saved, Undo/Redo and reopen. Require every original coordinate and ring length to survive, grouped nonzero fill with an open hole, native PNG/PDF downloads and unchanged privacy. Repeat `.json`, malformed JSON, unknown/projected CRS, oversized parts, full-capacity refusal and Cancel. Existing KML/XML multipart imports and rounded drawings must retain their contracts; existing map controls/fullscreen/export checks remain required.

The supplied electoral file is about 1 MB with 33 features. Current validation supports 28 groups / 9,407 original corners (18,814 stored points before existing map data). Those whole groups are skipped rather than altered or partially imported. Full original file size is 22,913 corners / 45,826 stored points; limits are not raised.
